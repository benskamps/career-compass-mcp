01

The verdict

What the second gauntlet found, in the order it matters.

Credit first, precisely. The remediation held: the loopback guard fail-closes on all nineteen adversarial Host shapes probed on a live socket — HTTP/1.0 with no host, absolute-form targets, duplicate headers, zone-ids, decimal IPs. The write claim's crash-recovery is immediate, not TTL-bound. The packaging allowlist blocked one hundred percent of 188 compiled test artifacts from the npm tarball. PRIVACY.md survives a line-by-line check against the code, and harvest_evidence is a small master class in refusal — it measures your git history and writes none of it anywhere, because "a tool that credits you with your colleagues' work is a résumé lie with a build step."

The v2 defect is one sentence: every discipline in this repository is real where it was born and absent where it moved. The read-modify-write discipline lives in mutatePipeline — the dashboard's onboarding actions do their read outside it, and a lost update the lifecycle spec calls unreachable was reproduced twenty times out of twenty. The injection fence lives in untrusted.ts — the prompts surface interpolates the same untrusted arguments bare, unscanned. The single-winner argument lives in a comment on the claim's wx create — the stale-claim break above it lets two processes both win, proven by replicating the syscalls.

Gate 0 is the release blocker for enrichment. The fence and the mutate door must reach every surface that holds the data before new prompts, tools, or an MCP App multiply those surfaces — and the frontier's cheapest, best-supported win lands directly on the unfenced prompt surface. No rewrite is warranted anywhere. These are inheritance failures, not design flaws.

03

What is actually built

An MCP server over stdio — 18 tools, 3 prompts, 9 resources and a completable template, live resources — over YAML on disk, with two viewers and one shared guard.

Every production mutation reaches disk through exactly three lock-and-claim doors — saveCareerSection, appendJournalEntry, mutatePipeline — verified by call-graph this pass, with no bypass in src/. The guard is genuinely shared now: one module, four sites, applied before routing on both dashboards. The clay node below is the v2 story — the Next dashboard's onboarding actions call loadCareerData() before they enter the locked door, so the lock protects the write and not the read-modify-write around it. The dashed prompt path reaches the model without the fence the tools pass through.

P1 · GATE 1

The stale-claim break admits two winners

The break path is rm then retry-wx, and the comment argues "wx is the primitive that actually picks a winner." It is unsound, because the rm is unconditional: it deletes whatever is at the path, including the other breaker's freshly-won claim. Two processes racing one stale claim both enter the critical section — {aWon: true, bWon: true}, reproduced by replicating the exact syscall sequence. The in-process test cannot reach this interleaving because serializeOn queues same-process callers, and no test spawns two processes. The fix is to break by renaming the stale claim to a unique sidecar — rename succeeds for exactly one process; wx then arbitrates against newcomers.

P2 · GATE 6

Deleting a watched directory spins the server forever

On Windows, fs.watch on a deleted directory emits an unbounded stream of rename events — probe 4b measured ~78,500 per 500 ms, sustained, continuing after the directory is recreated. The events are silently filtered, so the cost is pure CPU; worse, the watcher stays bound to the dead handle forever, so a real write after recreation produces zero notifications and a fresh subscribe will not re-arm. The product's own copy invites the trigger: "plain YAML — open it, edit it, or delete it any time." Gated on an active subscription, which no client holds today, hence P2.

Two roads into a state that shouldn't exist

The lock held both times. The read did not. Probe 1 loses a field 20/20 — two successes, one survivor.

Read as a lifecycle, LostUpdate is reachable by two roads the spec test cannot see — the dashboard's stale read, and the break path's double win — and a third defect (the dead watcher after a directory deletion) lives outside the machine entirely, which is itself the finding: the model draws writes but not the observation layer that reports them.

06

The frontier, pruned to three live lanes

Enriching every surface — but the frontier pruned itself while nobody was looking, and its cheapest win is blocked on Gate 2.

Sampling and roots are deprecated in the 2026-07-28 MCP spec (removal ≥ 2027-07-28) — harvest_evidence's dirs-via-params design already matches the world after. Three lanes are alive, verified against primary sources: MCP Apps (live on Claude Desktop and claude.ai since 2026-01-26) — and renderLiteDashboard() is already a self-contained single-file page whose clipboard-copy affordance exists only because there was no chat bridge, so porting it puts the kanban board inside Claude with real prompt dispatch; elicitation (Claude Code only) for the two data-loss moments; and prompts, annotations, structured output, supported everywhere — the server ships 3 prompts against 18 tools, and daily-ritual prompts are the cheapest enrichment on the board, blocked until the fence covers prompts. One UNKNOWN, honestly labelled: whether a local stdio server gets App rendering in Desktop — a half-day spike that gates the whole App lane.

The ideal writer has one door shape on every surface, the read inside it, every refusal named to the person, and the board re-rendering from the store rather than from optimism. Breaking becomes a first-class state with a single-winner transition — it existed in the code but not in the old diagram, and the gap between them is exactly where the second P1 lived.

08

Definition of done

Engineering. Every writer, on every surface, does its read inside the same lock and claim its write holds; every piece of third-party text passes one fence before it reaches the model, whether a tool or a prompt carried it; every refusal — corrupt file, held claim, read-only store — reaches the person as a sentence naming what happened; and each of those guarantees has a probe in the suite that fails when the guarantee is removed. The five probes this pass wrote are the acceptance tests, and they are already rerunnable.

Product. The promise is that your career data is yours, on your disk, compounding honestly for years. That now extends to the journal being as visible as the pipeline, to numbers that refuse to imply what they do not know — a 74-day-old store does not say "in play right now" — and to copy that never names a gesture or a tool that does not exist.

Every surface that touches the data inherits the rules of the layer that keeps it.
