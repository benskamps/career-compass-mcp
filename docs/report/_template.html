01

The verdict

What the gauntlet found, in the order it matters.

Career Compass is, on the MCP side, among the most carefully built things in this estate. The storage layer earns its confidence: fail-closed reads, atomic rename with a Windows retry path, per-file write serialization with the read inside the lock, backup retention, an allowlisted section name, and a genuine prompt-injection boundary with a per-call nonce. Almost every invariant is argued for in a comment before it is enforced in code, and several tests assert documentation truth rather than behaviour.

The defect is not in what was built. It is in where the care stopped. The repository holds two dashboards. src/dashboard-lite/ — the fallback, the one that ships to npm — carries a sixty-line argument for a DNS-rebinding Host check and implements it. dashboard/ — which bin/cli.ts:97 prefers whenever it has been built, which renders the whole Career KB including salary floor, salary ceiling and every recruiter contact, and which holds the only write path outside the MCP server — has no host check, no middleware, and no CI at all.

Gate 0 is the release blocker. Everything else is P2 or below. No rewrite is warranted anywhere: this is a gap in coverage, not a flaw in design.

03

What is actually built

An MCP server over stdio, seventeen tools, YAML on disk — and two viewers that make opposite promises from one command.

State is YAML under CAREER_DATA_PATH. The MCP server is the intended sole writer, and file-store.ts:65 says so in as many words. The Next dashboard is a second writer in a second OS process, so that invariant is stated but not held. The clay node below is the one that has no guard.

P1

The single-writer invariant is documented but not held

file-store.ts:64–66 — "the MCP server is the single writer for a given data dir. It is not a defense against two servers pointed at one directory." The repo ships that second writer itself. Two concurrent read-modify-write cycles on profile.yaml interleave; the later rename wins outright and both callers report success. The .bak makes that recoverable, not detectable. P2

HOSTNAME: "localhost" is passed to the Next standalone server

bin/cli.ts:120. The lite server documents at length that binding the name on Windows resolves ::1 first, so the server binds IPv6-only while clients try 127.0.0.1 and get ECONNREFUSED. The exact bug that was found, diagnosed and fixed on the lite path is still live on the preferred one.

P2

savePipeline is exported unlocked

It is public and takes no lock, while the twenty lines above it explain why calling it by hand is the bug. Nothing in the type system stops the next call site from reintroducing the lost-update race the lock exists to prevent.

P2

One raw JSON→<script> channel has no escaping and no guard

render.ts:299 — const CHART=${chartData}. Every other user-controlled value on that page goes through esc(), verified at all eight sites. chartData is safe only because its label is an enum name and its colour comes from a fixed map. A one-line future change — company names in the chart — turns the page that serves the whole job search into stored XSS on an unauthenticated local origin. No test pins the invariant.

05

The two branches

One command, two promises. The branch the CLI prefers is the branch with no guard, and it is the only branch that writes.

Read as a lifecycle, the same split produces two states that should not exist: Rendered is reachable without ever passing HostChecked, and LostUpdate is reachable while both writers report success.

06

The frontier

One guard module, one write claim, one CI that sees both halves. Everything green below is new; nothing existing is rewritten.

One guard imported by both dashboards, so a future third viewer inherits the defense instead of re-arguing it. One claim in the data directory, so "single writer" becomes a fact a second process can observe rather than a sentence in a comment — and Unavailable becomes a first-class outcome the user is told about, not a silent overwrite.

07

What the skeptics killed

Three adversarial passes — platform/runtime, storage/concurrency, product/privacy — then a contradiction-only re-read. Two claims were rejected outright; one of them was mine.

ΔClaimVerdictWhy
D1"The Next dashboard is unpublished, so the missing host check is not a real defect."MODIFYTrue that npm users never get it — and cli.ts:97 prefers it in every source clone, which is the author's own daily path. Severity holds; blast radius stated precisely instead.
D2"Next.js already blocks cross-origin Server Actions, so the write path is safe."REJECTThe check compares Origin to Host. Under rebinding both are the attacker's hostname and they match. The framework is not the mitigation.
D3"The in-process lock is insufficient and should be replaced with a file lock."MODIFYThe lock is correct and its scope comment is honest. The gap is a second process, not a broken lock. Add a claim on top; do not rewrite working concurrency control.
D4"The CHART interpolation is stored XSS."REJECTNo user string reaches it — label is enum-derived, colour is from a fixed map. Downgraded from a vulnerability to an unguarded channel that needs a test.
D5"The fail-closed storage layer is over-engineered for a personal tool."REJECTEvery guard cites the incident it came from — 8 concurrent adds leaving 1 application, 224 backups and 23.7 MB, Windows EPERM on rename. This is the standard the dashboard should meet, not the reverse.
D6"CI is fine; the dashboard is a dev-only surface."REJECT"Dev-only" describes distribution, not risk. The dev-only surface holds both P0s and the only write path outside the MCP server.
08

Definition of done

Engineering. A surface that can read the Career KB must prove its caller is loopback before it reads. A surface that can write it must hold a claim no other process holds. Every invariant that today exists only as a comment — single writer, always-mutatePipeline, chartData-is-enum-derived — is either enforced by a type or asserted by a test. Every guard has a runnable negative control.

Product. The promise is that your career data is yours, on your disk, inspectable. The storage layer keeps that promise today. The door does not.

Every surface that can read the salary floor refuses a stranger first, and every surface that can write it knows whether it is allowed to.
