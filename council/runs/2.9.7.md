## Headline

The product's core (fit check, drafts, truth rule, digest) is good. What holds it back is
a set of things it **looks** like it does but can't, plus no reason to come back:

- `/today` ranks expiring offers first, but no tool can record an offer (`pipeline.ts`
  update schema has no offer fields), so that branch never fires for a real user.
- The 2.9.7 CHANGELOG says rejection replies, recruiter replies and ATS formatting carry
  the truth rule; `career-kb.ts` and `pipeline.ts` don't import `TRUTH_RULE`. The one
  honesty fail in the latest run is exactly that ("I'm disappointed…").
- `save_career_section` replaces a section blind and can drop entries silently; a YAML
  typo in an optional section loads as empty (`file-store.ts:299-307`), producing false
  gaps and inviting an overwrite.
- "First reply 12/12" covers only résumé-plus-posting openers; posting-only fails 3 of 4,
  because `SKILL.md` allows two questions in one place and one in another.
- "Honesty 95% / task 89%" came from 1 run per case, and eval sessions can see the
  operator's real account name.

## Features and use cases (beyond the list)

Application-question answerer (works in chat); landing mode (first 90 days + brag log after
`accepted`); people ledger for referrals; résumé-only first value ("what am I competitive
for?"); try-it-on-a-sample fit check; weekly pace; `.ics` export; restore from backup;
duplicate-aware `pipeline_add`; provenance (`user_said | inferred`) on journal entries.

## Delighters

Save receipts ("+1 achievement · 0 removed · undo"); "You told Priya that one already";
thank-you note from the user's own debrief; "here's what saving just bought you"; honest
excitement-vs-outcome line; "write in your language, send in theirs"; placeholder count in
draft footers; "where did that come from?"; tailored résumés saved as named files;
`check_setup` names its own surface; errors that offer the closest match.

## Cuts

Duplicate MCP prompts (`daily-review`, `interview-coach`, `setup-career-kb`); vendor ATS
folklore in `format_for_ats`; the tool count and dashboard as the public hero; quoting
single-run percentages as conclusions; MCPB as a directory route; scraping or auto-apply.

## Dissent on record

- Growth vs Activation vs Retention on what comes first (front door, first session, or
  reasons to return). Synthesis: items 1–4 are each small and protect current users; the
  front door (6) runs in parallel; item 8 (Usage tab) decides the order after that.
- Activation's `.mcpb` spike vs Anthropic's directory evidence that `.mcpb` servers get held
  for review. Synthesis: do the clean-machine test, fix with a clear failure message.
- Retention wants no more first-reply polish; Activation shows posting-only still fails.
  Synthesis: item 4 is a one-rule merge; after it, first reply is closed.
- Anthropic: prefer new parameters on existing tools over new top-level tools; every new
  tool needs a when-clause and a routing case.
